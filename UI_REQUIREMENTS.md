# Требования к пользовательскому интерфейсу

Универсальный стандарт для настольных приложений (Windows и аналоги). Не зависит от языка программирования и GUI-библиотеки (WinForms, WPF, Qt, Tk, Flutter, веб-оболочка и т. д.).

Составлен по итогам разработки учётных приложений: замечания пользователей, типичные сбои и принятые решения. Требования обязательны для новых экранов, таблиц, полей и диалогов, если иное не согласовано явно.

**Локаль по умолчанию:** русский (Россия). Форматы дат и чисел ниже — для этой локали; для другой страны те же правила с её стандартом.

---

## 1. Принципы

1. Пользователь работает «не глядя на клавиатуру»: ввод дат и чисел не требует переключения раскладки, мыши и отдельных кнопок, кроме осознанного выбора из справочника или календаря.
2. Интерфейс не «прыгает»: окно, диалог, календарь и панели не появляются в (0,0) и не растягиваются на глазах.
3. Ошибки формулируются по-человечески. Недопустимый символ в поле не попадает в значение; рядом — короткое предупреждение.
4. Данные на экране, в печати и в Excel совпадают по смыслу: те же даты и числа, Excel получает настоящий числовой тип, а не текст.
5. Состояние рабочего места сохраняется: размер окна, разворот, ширины колонок, положение разделителей, выбранные колонки отчёта.
6. Узкое окно не обрезает команды: лишнее уходит за **Ещё**, а не за край экрана.
7. Интерфейс не требует интернета. Документация для пользователя — файл, который открывается без среды разработки (Word).

## 2. Приложение в целом

### 2.1. Запуск и окно

- Процесс учитывает DPI Windows (Per-Monitor V2 или аналог). Запрещено масштабировать окно как картинку: шрифты и иконки не должны быть «пиксельными».
- Главное окно показывается **уже в конечном размере и раскладке**. Скрыть окно до расчёта геометрии, затем показать. Нельзя сначала показать маленькое окно и потом развернуть на весь экран.
- Минимальный размер главного окна: **1024 × 768**. Пользователь не должен иметь возможность сжать его так, чтобы пропали навигация и таблица.
- При развороте / восстановлении размера панели команд и фильтров **пересчитывают ширину заново**, а не по устаревшему значению. Элементы не мигают: пересчёт без видимого появления-исчезновения каждого контрола (отложенный reflow, без анимации раскладки).
- Иконка приложения — тематическая, высокое разрешение (набор размеров 16…256 в ICO). Рисуется крупно и уменьшается, а не растягивается с 16 px.
- Шрифт интерфейса: системный без засечек высокого качества. Порядок предпочтения: Segoe UI, Segoe UI Variable, Aptos, Candara, Calibri, Arial. Один семейный шрифт на всё приложение. Базовый кегль UI ≈ 13 pt, заголовки крупнее, подписи мельче. Активный пункт навигации **крупнее** неактивных, не наоборот.

### 2.2. Компоновка

- Гибрид: тёмная боковая навигация + светлая рабочая область. Команды текущего раздела — отдельная полоса над содержимым, не дублируют пункты навигации.
- Набор кнопок зависит от раздела. Дублировать одни и те же действия вверху и внизу не нужно, если достаточно одного места (исключение: контекст таблицы — действия у самой таблицы).
- KPI / итоговые карточки не «скачут» при открытии: резервировать высоту полосы до заполнения цифрами или заполнять до показа окна.
- Строка состояния: итог или результат последнего действия, без модальных окон на каждый успешный шаг (тост / статус). Ошибки бизнес-правил — понятное сообщение, не трассировка.

### 2.3. Адаптивность панелей

- Если ряд кнопок, фильтров или конструктора не помещается по ширине, часть элементов уходит за кнопку **Ещё**.
- **Ещё** обязана работать при развороте окна, возврате к обычному размеру и смене раздела, а не только при ручном растягивании края.
- Контролы нельзя переносить геометрией в другое окно (popup): это ломает привязку к родителю. Либо вторая строка той же панели, либо **копии** полей в меню, исходные остаются на месте.

### 2.4. Данные, установка, документация

- Файлы данных — рядом с программой или в каталоге, доступном на запись без прав администратора. Каталог `Program Files` для БД не использовать, если приложение не пишет в AppData.
- Сборка для распространения — каталог (exe + библиотеки), не один самораспаковывающийся файл: иначе долгий старт.
- Установщик передаёт инструкцию пользователя в Word. Исходники Markdown остаются для разработки.
- Лицензия, автор, контакты разработчика (телефон, почта) доступны из поставки.

## 3. Навигация и команды

- Разделы переключаются с боковой панели. Справочники — внизу той же панели и/или в меню.
- Горячие клавиши не конфликтуют с полями ввода:
  - типовые операции создания / расхода — Ctrl+буква;
  - обновление — F5;
  - переход в поиск — `/`, если фокус не в многострочном поле;
  - Delete удаляет выбранную строку журнала **только если фокус не в поле ввода**;
  - Enter подтверждает диалог, Esc закрывает.
- Меню дублирует критичные действия (файл, справочники) для клавиатуры и привычки.

## 4. Таблицы

### 4.1. Общие правила

- Чередование строк (zebra), выделенная строка контрастна и читаема.
- Заголовки колонок — отдельный стиль, клик сортирует там, где сортировка имеет смысл (даты, наименования, категории). Повторный клик меняет направление.
- Сортировка дат — по календарному значению, не по строке «дд.мм.гггг» как тексту.
- Числа выравниваются вправо, текст — влево, даты — единообразно.
- Ширины колонок **запоминаются для каждой таблицы** (включая таблицы внутри диалогов просмотра копий). При широкой таблице — **горизонтальная прокрутка**, колонки не сжимаются в ноль.
- Вертикальная прокрутка обязательна, если строк больше видимой области. Высота строки согласована с кеглем (межстрочный интервал + запас), текст не обрезается по вертикали в одну строку заголовка.

### 4.2. Длинный текст в ячейке

- Не раздувать высоту строки многострочным переносом в колонках вроде «детали», «состав», «ящики».
- Если текст не вмещается: обрезать с многоточием и показать **всплывающую подсказку при наведении** с полным текстом.
- Подсказка не показывается, если текст целиком виден.

### 4.3. Форматы в ячейках

- Даты на экране: **дд.мм.гггг**. В хранилище — ISO `гггг-мм-дд`.
- Целые числа: разделитель тысяч — **пробел** (пример: `1 234`). В хранилище — число без пробелов.
- Итоги отчёта — отдельная строка по всем числовым колонкам.
- Условное выделение (низкий остаток и т. п.) — цветом строки или ячейки, без отдельной колонки «статус», если статус вычисляется из тех же чисел.

### 4.4. Фильтры

- Фильтры **живые**: изменение поля, списка или периода сразу обновляет таблицу, без кнопки «Применить», если выборка локальная и быстрая.
- Кнопка «Показать» допустима только если построение тяжёлое и пользователь должен явно подтвердить параметры.
- Печать и Excel выгружают **текущий отфильтрованный** набор, а не всю базу.

## 5. Поля ввода

### 5.1. Даты

Поле даты — текст + кнопка календаря. Виджет «всегда сегодня» в операциях запрещён: пользователь должен **осознанно** указать дату.

**Отображение и хранение**

| Где | Формат |
| --- | --- |
| Экран, печать | дд.мм.гггг |
| База, обмен | гггг-мм-дд |

**Ввод «не глядя»** (все варианты приводятся к `22.06.2026`):

- `22062026` (8 цифр)
- `220626` (6 цифр → год 20xx)
- `22.06.2026`, `22,06,2026`, `22/06/2026`, `22-06-2026`
- двузначный год (`26`) → четырёхзначный (`2026`)
- маска прогрессивная: лишние разделители схлопываются, буквы не нужны

**Календарь**

- Окно создаётся скрытым, позиционируется **у кнопки вызова**, затем показывается. Запрещены вспышка в левом верхнем углу и «прыжок».
- Если снизу не помещается — открыть сверху. Не выходить за край экрана.
- Esc закрывает календарь без записи.

**Операционные формы:** поле даты **сверху**, по умолчанию **пустое**. Без даты подтверждение невозможно («Укажите дату»). Копирование записи открывает ту же форму с **пустой датой**.

Фильтры периода могут иметь пресеты (сегодня, неделя, месяц, год) и ручной диапазон с той же маской.

### 5.2. Числа (количества)

- Разрешены только цифры и пробелы тысяч. Иной символ **не вводится**; рядом предупреждение: «Допустимы только цифры».
- При уходе с поля значение форматируется с пробелами тысяч.
- Разбор обратно в число обязан понимать пробелы, неразрывные пробелы и запятую как мусор разрядов, не как десятичную (для целых количеств).
- Спиннеры, которые ломают маску или вставку, не использовать, если достаточно поля с проверкой.

### 5.3. Прочий ввод

- Обязательные поля проверяются до записи; фокус на первое ошибочное.
- Справочные значения (вид, направление) — выбор из списка, не свободный ввод кода, если код легко ошибить.
- Tab обходит поля в логическом порядке: сверху вниз, слева направо, затем кнопки подтверждения. Shift+Tab — обратно.

## 6. Диалоговые окна

### 6.1. Появление и размер

- Диалог создаётся **скрытым**, измеряется, вписывается в родительское окно (не выше и не шире рабочей области), центрируется **относительно родителя**, затем показывается. Запрещены: появление в углу экрана, последующий прыжок в центр, рост «на глазах».
- Одинаковый каркас для однотипных справочников. Нельзя, чтобы одно окно было компактным по центру, а соседнее — на всю высоту экрана и обрезалось.
- Минимальная ширина достаточна, чтобы кнопки ОК / Отмена не обрезались и не вылезали за край.
- Модальность: пока открыт диалог, главное окно не принимает ввод.

### 6.2. Структура формы операции

1. Заголовок.
2. Дата (пустое поле + календарь).
3. Основные реквизиты (что, сколько, откуда).
4. Подсказка текущего остатка / контекста, если от этого зависит операция.
5. Комментарий (необязательный), внизу.
6. Кнопки: основная справа или внизу справа, отмена рядом. Enter / Esc.

Подписи слева или сверху от поля, выровнены. Между группами — одинаковые отступы. Не размещать кнопки «внахлёст» с полями.

### 6.3. Сообщения

- Блокирующие ошибки — диалог с текстом причины (нехватка, нет выбора, нет даты).
- Успех массовых действий — статус или тост, не лишний OK на каждый клик.
- Подтверждение — только на необратимое (удаление записи, полная замена данных).

---

## 7. Печать и обмен файлами

- Печать: HTML или системный диалог; числа и даты — те же форматы, что на экране.
- Excel: числа — тип Number, даты — Date, не General-текст. После экспорта файл открывается в ассоциированном приложении.
- CSV как основной обмен не использовать, если есть Excel.
- Экспорт журнала / отчёта учитывает фильтр текущего экрана.

---

## 8. Иконки и визуальный язык

- Формат кнопок и приложения: **ICO + PNG**, не SVG в рантайме Windows-приложения, если рендер даёт «мыло».
- Единая палитра: фон рабочей области светлый, навигация тёмная, акцент один. Типы операций можно кодировать цветом чипа/подписи, не радугой всего окна.
- Иконки командной полосы — цветные пиктограммы одного размера; навигация — монохромные глифы.

---

## 9. Контрольный список перед сдачей экрана

- [ ] Окно/диалог не мигает и не прыгает при открытии.
- [ ] Календарь открывается у кнопки, без вспышки в (0,0).
- [ ] Дата: пустая в операции, маска, дд.мм.гггг на экране.
- [ ] Числа: только цифры, пробел тысяч, Excel как число.
- [ ] Tab-порядок логичный, Enter/Esc работают.
- [ ] Таблица: сохранённые ширины, гориз. скролл, подсказка длинных ячеек, живой фильтр.
- [ ] Узкая ширина: **Ещё**, в том числе после разворота окна.
- [ ] Минимум 1024×768, DPI без пикселизации шрифтов.
- [ ] Ошибка понятна; успех не через лишний модальный OK.

## 10. Откуда взялись правила

Сжатый журнал решений из разработки:

| Тема | Решение |
| --- | --- |
| Современный вид | Тёмный рельс + светлая область, не «офисная» лента на весь экран |
| Пиксельный шрифт / иконки | DPI + векторная отрисовка крупно с даунскейлом, Segoe UI |
| Диалог в углу | Скрыть → разметить → показать в центре родителя |
| Справочники разной высоты | Один алгоритм вписывания в родителя |
| Дата «сегодня» по умолчанию | Пустое поле сверху, осознанный ввод |
| Календарь мигает в (0,0) | withdraw, позиция у кнопки, затем show |
| Узкая лента | Перенос / кнопка «Ещё», не обрезка |
| «Ещё» только при ручном ресайзе | Пересчёт ширины после разворота и смены раздела |
| Виджеты в popup «Ещё» падают | Не переносить виджеты в другой Toplevel |
| Скачет тулбар при старте | Не показывать окно, пока раскладка не стабильна |
| Перенос в ячейке «детали» | Обрезка + tooltip |
| Ширины колонок | Persist + горизонтальный скролл |
| Живые фильтры | Без лишней кнопки «Применить» |
| дд.мм.гг → дд.мм.гггг | Четыре цифры года везде на экране |
| Числа в Excel как текст | Типизированные ячейки |
| Установщик one-file тормозит | Каталог + Inno Setup, документация в поставке |
